# 原生桥渐进式披露

这里维护三套原生适配插件共用的披露协议、缺口凭据、动作预览和 Python 动态成员实现。构建入口运行 `scripts/generate-adapter-disclosure.mjs`，从本目录及各插件的工具清单生成 `bridge/generated/`。生成文件纳入版本管理，独立搬出插件后不需要主仓库或 Node；不要在三套生成文件中分别修补同一实现。仓库内构建会重新生成，`node scripts/generate-adapter-disclosure.mjs --check` 检查是否同步。

正常链路为：工具发现 → 原有业务目录 → 单项详情／配置 → 当前对象与版本校验 → 授权动作 → 本次结果。状态或其他有效只读证据按主程序既有规则披露业务后续工具，发现不扩大执行权限。

`capabilities.search` 对工具清单和实时业务声明分页检索，只返回摘要；`capabilities.describe` 返回单项输入契约、效果类别、来源或业务详情调用映射。它们不扫描运行时对象，不把已登记、宿主存在、桥已适配和本次执行混为一谈。清单契约指纹与宿主目录指纹分开返回。业务目录读取失败作为 `snapshotError` 保留，不冒充为空目录；静态工具契约仍可读取。

`host.inspect` 只用于常规能力已出现缺口、契约漂移或明确不可用时的补足。清单保持 `onDemand`，不作为搜索提供方、不随读取证据自动解锁。调用必须提供缺口类别与本轮具体证据。动态写入还需要桥在真实目录未命中、声明未适配或宿主契约不可用时签发的 `gapId`；模型自填说明不能单独放行。模型不能因入口存在就每次扫描宿主。

Python 桥通过公开 C API 读取已加载模块、已有实例及类的静态字典。只展开字典和已核验的内置元数据访问，检查阶段不求值 property、不调用业务方法、不导入业务模块、不执行源码字符串；参数来自 Python code metadata，不能据此推断默认值、业务含义或调用安全性。检查返回结构、参数元数据和文档，不调用对象字符串表示。MaaEnd 不扫描 Rust 私有内存或任意 HTTP 路径。

结构检查按成员名／路径与分页按需展开；不复制整个对象图。它不能绕过配置写入规则、任务限制或当前版本证据。运行时对象与 CLR 的模型不同，因此借鉴 Harmony 的成员定位与运行时适配思路，不给 Python／Rust 桥附加不能运行的 .NET 补丁依赖。

验证须分别记录：生成一致性、原生生产编译、插件载入、真实宿主附着、接口行为与游戏效果。编译成功不证明真实 Qt 回调、宿主版本或游戏执行已通过。

## 动态调用与字段修改（仅缺口路径）

使用顺序是：常规能力目录签发缺口凭据 → 携带凭据检查相关现场成员，取得 `memberId` → `host.prepare` 预览 → 在本次目标与授权内提交 `host.invoke` 或 `host.set` 一次。四个 host 工具均保持 `onDemand`；动态写入按高风险外部写入、串行、禁止无人值守及禁止自动重试登记，不作为常态操作，也不保存到快捷任务或定时任务。

成员凭据和计划都在桥内存中保存，最长五分钟有效，重连清空。执行工具只接收一次性 `planId`，不接收新参数；计划在开始执行时消费。Python 在同一 GUI 闭包中重新定位已有对象，核对成员、绑定方式、代码与默认参数身份；字段还核对原值，只改已有简单字段并回读。准备只转换 JSON 参数和生成预览，不调用目标。排队未执行、执行中未知、方法已返回和业务完成必须分别解释。

Python 动态调用只绑定已加载宿主命名空间中的现存对象与纯 Python 函数；可以按模块与类名定位现存唯一实例，不构造新实例，不执行源码字符串，不调用未知 descriptor 或外部运行时函数。凭据、路径、命令、脚本、更新及专用接口已有的限制继续生效。函数参数结构不证明业务语义；模型需要核对文档或源码依据，不能从名字猜。复杂返回对象和未知文本不直接展开，避免意外泄露值。

Python 字段写入只保证运行时状态，不声称已持久化。MaaEnd 字段写入复用官方条件保存 API，以 revision 与目录指纹核验，保留整份配置，只替换预览中的一个已有简单字段，并回读核对完整配置；已有任务选项接口与明确受限字段不得绕过。

MaaEnd 的动态方法适配公开 HTTP 契约，目前提供设备／窗口发现和现有实例 Win32 控制器连接。声明来自 MXU `web_server.rs` 提交 `d556cce`，检查明确标记为静态声明，不假称已在当前后端枚举路由。调用前确认后端身份，连接仅选择当前扫描缓存里的窗口和已有空闲实例；参数绑定在计划中。成功回执必须符合预期 JSON 类型；连接提交不等于连接完成。没有公开反射或路由描述的 Rust 私有方法仍不能动态调用，新增公开端点需要补充其契约适配。

公开后端的实例状态检查与控制器调用不是跨进程原子事务；其他客户端同时修改时仍可能竞争，不能把桥的前置检查解释为后端提供了 CAS。配置保存的条件写入则由官方 revision 接口执行。字段和参数的敏感性检查依据名称与已知限制，不声称可以识别任意未知字段的业务语义。

通用发现允许 Agent 定位遗漏入口，受控动态调用用于本轮缺口补足；它们不保证任意新版本自动兼容。真实宿主执行、退出、重连和业务效果需独立验收。
